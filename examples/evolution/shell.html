让你的组件行为看得见、可验证

MoonStateLens 通过实际调用学习组件的行为，找出新旧版本在哪一串操作后产生差异，再重新执行确认。适合配额、缓存、会话和事务等“结果与之前操作有关”的组件。

从下方选择：调整参数做实验、分析自己的模型／报告，或生成真实项目的接入文件。文件在浏览器本地读取，不上传到服务器。

自定义真实配额升级实验

每次申请占用一个名额，释放后归还。修改新旧容量，观察第三次、第四次申请等操作是否产生差异。实际调用 MoonLimit 公共 API，使用 L* 学习与 Wp 条件验证。

容量变化是受控配置变化，不自动等于缺陷。历史模型只提供实验结构，新版输出重新采集。配额状态上界为容量＋1；令牌桶／LRU 是固定参数示例。

比较自己的行为模型

选择两个 MoonStateLens 模型 JSON，或粘贴模型内容。使用 MoonBit 内核寻找最短区分操作。每个模型最多 128 状态、16 种输入，单文件最多 1 MB。

这里精确比较的是用户提供的模型，不会连接真实组件，也不会据此宣布你的仓库验证通过。

查看自己的执行报告

支持实验室、学习、比较、回归、规则和诊断等 version 1 报告；展示文件中已有的结果和模型，不重新认证文件真实性。普通日志不等于可主动查询的被测目标。

把验证接入自己的仓库

先将要验证的组件接入 JSONL 协议：reset 恢复初始状态，step 执行一个有限操作并返回抽象结果，close 负责清理。生成的文件会在你的电脑或 GitHub Actions 中运行真实组件；本网页不编译或执行 GitHub 仓库。

状态上界需要由维护者说明依据，工具不会自动证明。程序必须实现协议；MoonBit 仓库的原有构建由生成工作流执行，桥接程序应位于你填写的路径。非 MoonBit 项目需调整构建步骤。

协议示例与使用步骤
请求：{"version":1,"id":7,"method":"step","input":"login"}
响应：{"version":1,"id":7,"ok":true,"output":"ok"}
还需支持 reset 和 close；同一请求 id 必须原样返回。
1. 在仓库实现并构建新旧桥接程序，保证可靠重置与确定性。
2. 下载两份配置到仓库根目录，工作流放入 .github/workflows/statelens.yml。
3. 提交并运行 Actions，下载 statelens-evidence 产物。
4. 在“分析我的数据”导入 comparison.json。
退出码 0：满足声明的证据策略；2：真实回放确认差异；3：未完成；1：执行失败。
