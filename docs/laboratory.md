# 版本演进实验室使用指南

## 行为演进工作台

新旧模型使用独立状态编号；画布沿同一操作序列高亮路径，滑块控制回放位置，鼠标滚轮缩放。
可选择对照模型，点击实际学习事件查看该轮假设、真实采集的反例输出和验证证据。
事件记录来自同步 `learn_with(..., on_event=...)`，不是录制动画或可恢复的学习器检查点；native 异步接口目前不提供这一回调。
画布最多显示 24 状态和 96 边，完整模型仍进入分析；截断说明始终可见。

在工作台勾选“模型比较使用定向兼容”，再比较导入模型。
`backward_compatibility(old, next)` 只检查旧输入集合形成的所有历史；新版额外操作不参与契约。
结果区分旧操作删除、旧行为变化、旧操作历史兼容。新操作参与后的行为以及真实程序符合性不在该模型结论范围内。
原有严格模型比较仍要求同样的输入集合，默认行为不变。状态对预算不足会失败，不会报告兼容。

导出的 version 1 实验包包含请求、结果、学习事件、构建来源声明和 SHA-256。
打开后检查内容一致性，恢复模型和证据；导入内容仍是文件作者声明，校验值不认证执行真实性。
可以重新运行包内的配额或模型分析请求，重新运行由浏览器 MoonBit 内核执行。
外部仓库报告只能审查，其目标必须回到本地／CI 运行。包为 JSON，上限 8 MB，不执行包内代码。
最终 0.5.0 源码测试为可移植后端各 69 项、native 93 项。浏览器 fixture 新增画布、事件、实验包恢复、篡改拒绝和兼容扩展检查。

[打开实验室](https://captaink-65.github.io/moon-statelens/demo/)

MoonStateLens 用实际操作学习有状态组件的行为，再找出能够区分新旧版本的操作序列。
它适合缓存、会话、配额和事务等组件。仓库提供核心库和 native 接入能力；网页将其中一部分变成可交互入口。

## 自定义实验

填写旧版／新版配额容量（1–6）与每个学习会话的查询预算（1–100,000），点击运行。
观察模型状态数、冷启动与历史引导的实际重置数，以及双方真实实例的回放输出。
默认 2→3 容量案例是 3→4 状态、83→54 重置；其他参数可能收益较小、无收益或退化。
相同容量可以得到无差异结果；查询预算不足明确显示未完成，不能作为通过。
下载结果 JSON、选中的完整模型或完成实验生成的 JUnit。容量变化可能是预期功能，不自动等于缺陷。

计算由实际编译的 MoonBit 内核执行，MoonLimit 是被测对象。每个版本均创建新会话。
Wp 的状态上界取容量＋1，只适用于这个确定、可重置的有限配额抽象。
Web Worker 支持取消；30 秒会停止浏览器任务并报告未完成。页面保持可操作。
“完整组件示例”保留原配额、固定参数令牌桶和 LRU 实验。

## 分析自己的数据

- 模型：导入或粘贴两个 `moonstatelens.mealy` version 1 完整模型。支持 128 状态、16 个输入、1 MB 单文件限制；格式和模型不变量由 MoonBit 解码器校验。可填入／下载示例。
- 模型分析会精确寻找最短区分操作，或判断给定模型可观察等价。它不连接真实目标，不证明仓库行为与模型一致。
- 报告：导入带 `moonstatelens.*` format 和 version 1 的既有 JSON。查看原始状态、证据和可识别的模型，并导出选中的模型。格式信封被识别不代表报告内容已被重新认证。
- 文件在当前浏览器本地读取，不上传服务器。导入失败会清空之前的下载结果；普通调用日志不会被冒充为主动学习得到的模型。

## 接入自己的项目

1. 选择具体组件，并提供有限操作、确定输出和可靠重置。实现 [JSONL 协议桥接](native.md#jsonl-lifecycle)，分别构建新旧版本的程序。
2. 填写桥接程序相对仓库根目录的路径、操作名称、共同抽象和可解释的状态上界。仓库 URL 只记录来源，不触发在线执行。
3. 下载 `statelens-left.json` / `statelens-right.json` 到仓库根目录，`statelens.yml` 放在 `.github/workflows/`。
4. 生成的手动工作流固定 MoonStateLens 源码和工具链；先构建你的 MoonBit 项目，再在 `.statelens-tool` 检出中检查配置、比较真实程序并保存 `evidence/`。其他语言需调整项目构建步骤。
5. 在 Actions 运行，下载 `statelens-evidence`，将 `comparison.json` 导入实验室查看。新旧模型与轨迹分别保存在左右子目录。

程序路径是可执行文件路径，不是一整条 shell 命令；向导暂时只生成无额外参数的 JSONL 目标。
工作流中的配置路径基于根目录下的 `.statelens-tool`，本地执行也需保持这个目录结构。
默认路径只是占位，用户需实现自己的桥接。生成配置不表示目标程序存在、能可靠重置或已经验证成功。
状态上界由调用者提供依据；错误上界会使条件验证的结论失去依据。
差异退出 2、未完成退出 3、执行失败退出 1 都会使 CI 门禁失败；`always()` 仍保留已有证据。

## 开发与检查

```sh
moon test examples/lab_logic --target all --deny-warn
moon run tools/build_evolution_demo.mbtx
moon run tools/verify_lab_wizard.mbtx
```

最后一条实际运行网页向导的生成逻辑，将生成的两份配置交给 native `validate-config ... compare` 检查，并验证路径限制。
在浏览器打开 `examples/browser/lab.test.html` 可执行 17 项页面联测；通过时显示 `ALL 17 CHECKS PASSED`。
通过本地 HTTP 服务打开仓库可同源运行；开发用 Edge 文件协议测试需要 `--allow-file-access-from-files`，正常在线使用不需要此标志。
联测覆盖真实配额、相同参数、预算不足、模型比较、无效输入、报告导入、向导与原组件示例。

新增实验协议的两个命名测试在四后端均通过；全仓库首轮自定义实验的本地测试为可移植后端各 66 项、native 90 项；工作台新增后的记录见本页开头。
这些是最新源码的检查，不替换已经发布的 0.5.0 包与其冻结验证记录。
