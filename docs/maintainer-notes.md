# 维护者原理说明

## 工具解决什么问题

有状态组件的输出与之前执行的操作有关。MoonStateLens 通过公开的 reset/step
接口主动实验，推断一个可观察行为模型。输入集合、输出抽象和可靠复位由使用者定义；
它不能自动理解任意程序，也不能从有限次实验推出任意实现永远等价。

## 两种学习器为何独立

L* 保存访问序列和区分后缀组成的观测表，修复闭合性、一致性，再构造假设。
KV 保存访问词和区分树，利用反例分裂状态。两者共享查询、预算和模型基础设施，
KV 不调用 L* 计算模型。可以用相同有限目标和 Wp 计划比较真实查询成本；
某种算法在个别样例上更省查询不代表它普遍更快。

实现见 learning_table.mbt、learning_tree.mbt、learning_driver.mbt。
测试通过独立模型比较核验两种学习器，包括固定种子生成目标和全部二状态二输入二输出表。

## 为什么模型不同还要重新执行

模型是实验支持的假设，两个模型不同不直接意味着两个组件不同。
比较器先搜索区分输入，再绕过缓存在双方目标重新执行。实际输出不同才确认差异。
不能复现的模型分歧作为新实验反馈到学习流程。预算不足、超时和漂移均有独立终止语义。

## W/Wp 结论的前提

状态上界由调用方声明，工具不会自动证明该上界。完整性还要求确定、完整、
可可靠复位、输入集合一致，并完整执行生成的实验。
深度枚举和随机实验只能提供其预算内证据。异步 IO 用于等待进程和网络，
目标会话内部仍按顺序执行，不等于学习任意并发交错。

## 核心职责与依赖的边界

状态区分、反例精化、实验生成、资源计数、证据分类和真实回放确认由本项目实现。
标准库、async、x/path 提供数据结构、JSON、IO 和路径基础设施。
MoonLarder 与 SQLite 是被测组件，不承担推断职责。LearnLib/AALpy 是公开方法的参考，
未作为运行时学习引擎调用。完整来源记录见 THIRD_PARTY_NOTICES.md。

## SQLite 示例应该怎样解释

目标是真实 SQLite CLI，操作限定为单条记录和有限事务操作。
工具从交互学得六状态抽象；独立参考只用于学习完成后的测试。
回滚误发提交是项目刻意注入适配层的错误，不是 SQLite 漏洞。
begin → put → rollback → read 的重新执行能够得到 empty/present 差异。

## 怎样判断一份结果可用

先查看命令退出码，再检查证据状态、声明的抽象和预算，最后审查实际轨迹。
0 只表示满足配置指定的证据要求；2 表示真实确认差异；3 表示证据不足；
1 表示配置、传输、目标或输出保存失败。旧 CLI 的退出码约定另外见 README。
产物文件存在不代表整个运行成功，多文件写入不是事务。

## AI 辅助与可验证性

本项目使用 AI 辅助实现、测试和文档，主视觉为 AI 生成概念图片。
可审查依据是源码、独立核验、实际组件交互、命令退出码和可追溯的公开记录。
本说明用于帮助维护者解释设计，不代替代码审查，也不声称已经发生人工评审。
